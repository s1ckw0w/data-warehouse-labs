# Лабораторная работа № 1 — Data Vault

**Дисциплина:** «Хранилища данных». **Вариант № 6:** система составления учебного графика дисциплин факультета.  
**Студент:** Савельев Максим Олегович, группа 223-321.  
**СУБД:** PostgreSQL 18. **База:** `academic_schedule_dv`.

## Реализованная модель

Raw Data Vault 2.0: **11 Hub, 7 Link, 12 Satellite — 30 базовых таблиц** в схеме `dv`; одна staging-таблица `stg.timetable_snapshot`; два представления `dv.v_schedule_current` и `dv.v_plan_current`. В сателлитах используются `load_dts`, `record_source` и `hashdiff`; изменения атрибутов сохраняются новыми строками.

## Фактическая проверка в pgAdmin 4

- `stg.timetable_snapshot` — 5 строк;
- `dv.hub_teacher` — 2 преподавателя; `dv.hub_schedule` — 4 занятия;
- `dv.sat_teacher` — 3 строки, включая две версии email для `T-001`;
- `dv.v_schedule_current` — 4 строки;
- `dv.v_plan_current` — 2 дисциплины;
- запрос к `information_schema.tables` для схем `dv` и `stg` показывает 33 объекта: 30 таблиц, 2 представления и 1 staging-таблицу.

## Запуск

1. Если базы `academic_schedule_dv` ещё нет, выполните `sql/00_create_database.sql` из базы `postgres`.
2. Подключитесь к `academic_schedule_dv`.
3. Выполните `sql/01_Выполнить_всё.sql` **один раз**. Этот объединённый файл создаёт схему, процедуру загрузки и демонстрационные партии B1/B2.
4. Выполните запросы из `sql/04_checks.sql` по одному.

Вместо объединённого файла можно выполнить по порядку `sql/01_schema.sql`, `sql/02_load_batch.sql`, `sql/03_demo_data.sql`. Не запускайте оба варианта и не повторяйте полный скрипт на уже заполненной базе.
